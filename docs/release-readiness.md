# Core-aura release readiness

Baseline reviewed on 20 November 2026 IST. This audit draws on the original blueprint, the v0.29.0 report, subsequent project conversations available in this workspace, source history through v0.41.0, and public web, API, catalog and Android responses. The complete transcript of every project conversation was not available.

## Product and release objective

A listener can build a practice or mix with precise generated sound, reusable text and recorded audio, then play it again from Home. Library is the place to find, preview, import, export and manage sources. Manifest, Sounds and Chakras are the authoring workspaces. The web/PWA and native apps should support everyday listening without an account or AI dependency. Generated and imported content should work offline when its dependencies are available. Keep advanced tuning, simultaneous and sequential chakra playback, scheduling and themes accessible in their own workspaces.

## Why delivery stalled

1. The staged visual rebuild turned off Home after the main controls already existed. The browser suite asserted that Home remained empty. This made CI success compatible with a broken first-use journey.
2. Repeated section-level fixes covered capable editors while leaving the transitions between them unowned. Saving, playing, finding the last session after relaunch, deleting a source safely and recovering it on another device are distinct checks.
3. Android and web used different publishing paths. Before v0.41.0, the build-input publishing job ran only on main while website updates came from a release branch. v0.41.0 fixed this branch mismatch. On this audit, the site and signed Android channel both returned v0.41.0; the API was healthy on its separately versioned v0.26.0 interface.
4. Product code, licensed repertoire and physical acceptance were treated as one outcome. Generated phrase studies can ship without rights acquisition. Authenticated performer recordings, musical review, an iOS distribution identity, actual notification delivery and lock-screen behavior require separate evidence.

The deeper distinction for Core-aura is the saved session itself. A single practice can combine locally generated audio, imported files, an audio affirmation and device or server speech. A successful pack download therefore establishes only one part of offline readiness. The next useful capability is an item-level readiness check that identifies missing dependencies and offers a direct way to repair them. Measure it against a saved mixed playlist opened after a cold launch in airplane mode.

## Acceptance gates

1. **Release consistency.** From a tagged build, confirm public web and Android versions, immutable APK reachability and content metadata. Verify the API and catalog separately. Use `bash ops/verify.sh VERSION --android` after publishing both channels.
2. **Repeat listening.** On each platform, create or import an audio affirmation; select a voice, tone and background; save; add a practice, audio file and chakra sequence to a playlist; play from Home; switch tabs; pause, resume, skip and stop. Relaunch and verify replay starts only on request.
3. **Offline and recovery.** Download a pack, put the device in airplane mode, cold-launch and play a downloaded file and a generated mix. Test speech with and without an installed same-language voice. Restore settings plus selected audio in a separate profile and confirm that dependencies work or fail with a specific action.
4. **Native acceptance.** Upgrade a signed Android install with existing practices, downloaded packs and custom theme. Preserve data. Repeat on supported Android devices with the screen locked, Bluetooth changes, a call, a reminder and restrictive battery settings. On iPhone, repeat with a signed test build. Record which behaviors continue, pause and recover.
5. **Content acceptance.** Check rights, attribution, tradition, performer consent and practitioner review for a real pilot pack. Exercise withdrawal. Claims about treating health conditions or cellular regeneration require an independent evidence and review process before publication.
